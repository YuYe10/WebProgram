\subsection{标识}

项目名称为 Noteworthy，版本号 1.0，属于轻量化在线笔记软件类别。

\subsection{项目概述}

Noteworthy 是一个面向个人知识管理场景的在线笔记平台，提供从信息采集、组织到检索的完整笔记工作流。系统采用前后端分离架构，后端提供 RESTful API，前端为单页应用，通过 JWT 实现无状态认证。

该项目的核心特色包括：前后端完全自主开发，数据主权可控；基于 ProseMirror 内核的 Tiptap 编辑器提供专业级富文本编辑能力，支持 15 种以上扩展与代码语法高亮；采用 BCrypt 12 轮密码哈希配合 JWT 双令牌无感续期与用户级数据隔离，安全机制对标生产环境标准；双层图片清理策略配合归档笔记自动过期机制，有效解决服务器存储泄漏问题。

\subsection{运行说明}

运行环境要求 Docker 与 Docker Compose、Python 3.10 及以上版本、Node.js 18 及以上版本。

启动步骤如下：

\begin{enumerate}[itemsep=2pt]
  \item 启动数据库，执行 \lstinline|docker compose up -d db|
  \item 启动后端服务：
\begin{lstlisting}[language=bash]
cd backend && cp .env.example .env
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt && alembic upgrade head
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
\end{lstlisting}
  访问 \url{http://localhost:8000/docs} 可查看 Swagger API 文档。
  \item 启动前端服务：
\begin{lstlisting}[language=bash]
cd frontend && npm install && npm run dev
\end{lstlisting}
  浏览器打开 \url{http://localhost:5173} 即可使用。
\end{enumerate}

\subsection{用户认证与授权}

系统采用 JWT 双令牌认证机制。用户登录成功后，后端签发 Access Token 与 Refresh Token，均使用 HS256 算法签名，payload 包含 sub、iat、exp 与 type 四项声明。Access Token 有效期为 30 分钟，用于接口鉴权；Refresh Token 有效期为 7 天，用于无感续期。

鉴权流程中，请求经由 get\_current\_user 依赖注入解析 Access Token，校验 type 字段为 access 且未过期，随后将用户对象注入路由函数。前端 Axios 响应拦截器在捕获 401 状态码后，自动以 Refresh Token 调用 /auth/refresh 接口获取新令牌对。针对并发场景，拦截器实现了请求队列机制，首个 401 请求持有刷新权，其余请求以 Promise 入队等待，刷新完成后统一重试，从而避免竞态导致 Token 失效。所有 Service 层查询均携带 user\_id 条件，确保用户间数据物理隔离。

保存策略方面，编辑器 onUpdate 事件触发 3 秒防抖定时器，标题变更同样触发保存流程；Ctrl+S 快捷键可立即保存；组件卸载时若 isDirty 状态为真则执行兜底保存。状态栏提供三态指示，分别为 Saved、Unsaved 与 Saving。

\subsection{图片生命周期管理}

图片上传通过 POST /uploads/images 接口完成，后端校验 Content-Type 为 JPEG、PNG、GIF、WebP 或 SVG 格式，且文件大小不超过 5\,MB，随后以 UUID 重命名存储至 uploads 目录，返回 /uploads/filename 形式的 URL。

即时清理机制在笔记更新时对比新旧 content 中的图片引用集合，删除不再被引用的文件；笔记删除时同步清理关联图片。定时兜底机制由后台 cleanup\_loop 异步任务每小时执行一次全量扫描，删除 uploads 目录中未被任何 note 引用的文件，同时删除 archived\_at 字段超过 7 天的归档笔记及其标签关联。

\subsection{全文搜索}

笔记创建或更新时，后端递归遍历 Tiptap JSON 文档，提取 type 为 text 的节点，拼接为 plain\_text 冗余字段。搜索接口基于 ILIKE 对 title 和 plain\_text 字段进行模式匹配，支持按 notebook\_id 过滤与分页。数据库初始化时已启用 pg\_trgm 扩展，后续可平滑升级为三字符索引加速方案。

\section{技术难点与对策}
% ============================================================

难点一为 JWT 并发刷新竞态问题。在单页应用中，多个异步请求同时收到 401 状态码时，若各自独立刷新令牌，后到的刷新请求会使先前的 Refresh Token 失效，导致其他请求永久失败。对策是在 Axios 拦截器中实现请求队列模式，设置 isRefreshing 互斥标志，首个 401 请求持有刷新权，其余请求以 Promise 入队等待；刷新成功后调用 processQueue 统一重试，失败则全部拒绝并执行登出操作，额外内存开销为常数级。

难点二为服务器图片存储泄漏问题。用户删除笔记或编辑移除图片后，文件系统可能残留无人引用的图片文件，长期运行将耗尽磁盘空间。对策是采用双层清理策略，即时层在 NoteService 的 update 与 delete 方法中对比新旧 content 的图片集合，立即删除孤立文件；兜底层由 cleanup\_loop 异步任务每小时全量扫描，比对 uploads 目录与所有 note content 中的引用，删除无主文件与归档超过 7 天的笔记。两层互补，确保零泄漏。

\section{总结与评估}
% ============================================================

\subsection{学习收获}

通过本项目，掌握了前后端分离全栈开发的完整流程，涵盖 ER 设计、Alembic 迁移、RESTful API 开发与 SPA 交互实现。深入理解了 JWT 认证体系，包括双令牌策略、并发刷新队列、依赖注入鉴权与数据隔离机制。实践了 ProseMirror 文档模型，理解了 Tiptap 扩展机制、JSONB 存储策略与纯文本提取搜索优化方案。积累了异步编程经验，涉及 SQLAlchemy 2.0 异步会话、FastAPI 异步路由与 asyncio 后台任务。工程化能力方面，掌握了泛型 Repository 模式、双层资源清理策略与 Axios 拦截器设计方法。

\subsection{完成度评估}

全部 7 个功能模块均已实现，包括用户认证、笔记本增删改查、笔记增删改查、富文本编辑器、图片系统、搜索与标签以及 UI/UX。代码结构清晰，API 文档自动生成。

未来演进方向包括采用 tsvector 全文搜索配合 GIN 索引替代 ILIKE 以提升检索性能，引入 WebSocket 实现实时通知与多端同步，增加笔记导出为 Markdown 或 PDF 的功能，以及基于 CRDT 或 OT 算法实现协作编辑。
